Trả lời ngắn

Đừng cài OpenCode lên chính máy Proxmox, cũng đừng rải nó vào từng VM. Hãy tạo một VM (hoặc LXC) riêng tên vm-agent, chỉ cài OpenCode và Docker CLI, rồi trỏ tới Docker của từng VM Ubuntu bằng docker context qua SSH. Windows chỉ dùng để mở giao diện web.

VM Ubuntu 24.04 (hoặc LXC unprivileged)

So sánh 3 vị trí có thể đặt OpenCode

Chọn từng phương án để xem nó nằm ở đâu và vì sao nên hoặc không nên.

Cài thẳng trên Proxmox host

  • Nhìn thấy mọi VM, gọi được qm/pct.
  • Agent chạy với quyền root của hypervisor: một lệnh sai có thể tắt hoặc xoá cả 3 VM.
  • Host Proxmox không có Docker; vẫn phải SSH vào VM mới điều khiển được container.
  • Cài thêm Node/Bun lên host làm khó nâng cấp Proxmox, trái khuyến nghị giữ host sạch.

Mỗi VM một OpenCode

  • Đơn giản khi chỉ có một VM, lệnh docker chạy cục bộ.
  • 3 bản cài, 3 bộ cấu hình, 3 nơi lưu API key của LLM.
  • Không có góc nhìn chung: không so sánh hay di chuyển dịch vụ giữa các VM trong một phiên.
  • Agent nằm cùng máy với workload: nó có thể làm đầy disk, chiếm RAM hoặc tự làm hỏng chính VM nó đang đứng.

VM riêng vm-agent (đề xuất)

  • Một nơi duy nhất chứa cấu hình, quyền, key LLM và lịch sử phiên.
  • Tách khỏi workload và khỏi hypervisor; snapshot hoặc xoá vm-agent không ảnh hưởng dịch vụ.
  • Một phiên OpenCode thấy cả vm1 và vm2 nhờ docker --context.
  • Thêm VM mới chỉ cần thêm 1 context và 1 SSH key.
  • Tốn thêm khoảng 4 GB RAM và phải quản lý SSH key.

Ba mức quyền cho lệnh Docker

OpenCode có cấu hình permission với 3 hành động allow, ask, deny; quy tắc khớp sau cùng sẽ thắng. Chia lệnh Docker theo mức rủi ro như sau.

allow

Xem trạng thái

docker --context * psdocker --context * logsdocker --context * inspectdocker --context * stats --no-stream

Chỉ đọc, chạy tự động để agent chẩn đoán nhanh.

ask

Thay đổi có thể hoàn tác

docker --context * restartdocker --context * pullssh vm* docker compose up -d

OpenCode dừng lại hỏi bạn trước khi chạy.

deny

Mất dữ liệu

docker --context * rmdocker --context * volume rmdocker --context * system prune

Chặn hẳn, kể cả khi bật chế độ --auto.

Lưu ý bảo mật: user thuộc nhóm docker trên VM đích tương đương root của VM đó. Cổng phân quyền của OpenCode chỉ là lớp bảo vệ trong agent, không phải sandbox. Vì vậy hãy giới hạn SSH key theo IP của vm-agent, không mở Docker API qua TCP, và snapshot VM trước các thay đổi lớn.

Các bước triển khai

Làm theo thứ tự. IP dùng ví dụ, thay bằng IP thật của bạn.

  1. Tạo vm-agent trên Proxmox

    Tạo VM Ubuntu 24.04, 2 vCPU, 4 GB RAM, gắn vào vmbr0, đặt IP tĩnh 10.10.10.50. Không bật GPU passthrough cho VM này.

    Chạy trên vm-agent

    # Docker CLI (không cài dockerd) + OpenCode sudo install -m0755 -d /etc/apt/keyrings curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg echo "deb [signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release; echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list sudo apt update && sudo apt install -y docker-ce-cli docker-compose-plugin git curl -fsSL https://opencode.ai/install | bash

  2. Tạo user riêng trên mỗi VM Ubuntu

    User opencode-agent trong nhóm docker, chỉ chấp nhận key đến từ IP của vm-agent.

    Chạy trên VM Ubuntu 1 và VM Ubuntu 2

    sudo adduser --disabled-password --gecos "" opencode-agent sudo usermod -aG docker opencode-agent sudo install -d -m700 -o opencode-agent /home/opencode-agent/.ssh # dán public key của vm-agent, khoá theo IP nguồn echo 'from="10.10.10.50",no-agent-forwarding,no-X11-forwarding ssh-ed25519 AAAA... vm-agent' \ | sudo tee /home/opencode-agent/.ssh/authorized_keys sudo chown opencode-agent /home/opencode-agent/.ssh/authorized_keys && sudo chmod 600 /home/opencode-agent/.ssh/authorized_keys

  3. Khai báo docker context trên vm-agent

    Mỗi VM là một context. Docker CLI tự mở SSH tới socket /var/run/docker.sock của VM đích, không cần mở cổng 2375.

    Chạy trên vm-agent

    ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -N "" docker context create vm1 --docker "host=ssh://opencode-agent@10.10.10.11" docker context create vm2 --docker "host=ssh://opencode-agent@10.10.10.12" docker --context vm1 ps # kiểm tra docker --context vm2 ps

    Với docker compose, file compose nằm trên VM đích, nên dùng ssh opencode-agent@10.10.10.11 'cd /opt/stack && docker compose up -d', hoặc giữ các file compose trong một repo git trên vm-agent.

  4. Cấu hình quyền cho OpenCode

    Đặt file trong thư mục dự án ops trên vm-agent, ví dụ ~/infra/opencode.json.

    { "$schema": "https://opencode.ai/config.json", "permission": { "bash": { "*": "ask", "docker --context * ps*": "allow", "docker --context * logs *": "allow", "docker --context * inspect *": "allow", "docker --context * stats --no-stream*": "allow", "docker --context * restart *": "ask", "ssh opencode-agent@* docker compose *": "ask", "docker --context * rm *": "deny", "docker --context * volume rm *": "deny", "docker --context * system prune*": "deny" }, "external_directory": "deny" } }

    Thêm AGENTS.md trong cùng thư mục, mô tả vm1 chạy gì, vm2 chạy gì và quy ước luôn dùng --context. Agent sẽ đọc file này ở mỗi phiên.

  5. Mở OpenCode Web cho Windows và cho bạn từ xa

    Chạy dạng service, chỉ bind IP nội bộ (hoặc IP tailnet của Headscale), bắt buộc mật khẩu. Không mở port ra Internet.

    # /etc/systemd/system/opencode-web.service [Service] User=ops WorkingDirectory=/home/ops/infra Environment=OPENCODE_SERVER_PASSWORD=doi-mat-khau-manh ExecStart=/home/ops/.opencode/bin/opencode web --hostname 10.10.10.50 --port 4096 Restart=on-failure [Install] WantedBy=multi-user.target

    Trên VM Windows mở http://10.10.10.50:4096. Từ xa, cài Tailscale client lên vm-agent, join Headscale và truy cập bằng IP tailnet.

  6. Trỏ OpenCode tới mô hình AI

    Nếu server AI có GPU, passthrough GPU cho một VM riêng chạy Ollama hoặc vLLM, rồi khai báo provider tương thích OpenAI trong opencode.json. Nếu dùng API cloud, chỉ cần lưu key trên vm-agent. Mô hình nhỏ có thể gọi tool kém; hãy thử lệnh chỉ đọc trước.

  7. Kiểm tra và snapshot

    Hỏi OpenCode: "liệt kê container đang chạy trên vm1 và vm2". Nó phải tự chạy ps, hỏi bạn khi restart và bị chặn khi rm. Sau đó snapshot vm-agent trong Proxmox để có điểm quay lại.

Nếu VM Windows cũng chạy Docker

Khuyến nghị giữ Windows làm máy client. Nếu bắt buộc chạy container ở đó, bật OpenSSH Server trên Windows, đảm bảo lệnh docker có trong PATH của phiên SSH, rồi tạo thêm docker context create win --docker "host=ssh://user@10.10.10.13". Cách này kém ổn định hơn Linux vì Docker Desktop chạy qua WSL2, nên kiểm tra kỹ trước khi giao cho agent.
