01 / task sequence

Foundation trước, ABI có evidence sau.

Task 1 dựng Go project, deterministic clock và mock host. Task 2 đóng gói native C ABI, schema negotiation và ba alias. Native load không được coi là pass khi local thiếu compiler: CI/staging phải cung cấp evidence riêng.

Client request: chat | research | code ↓ CLIProxyAPI -- model.route --> CPA Bundle Router |- capability filter |- affinity / tier / weight |- retry budget / cooldown ↓ host.model.execute(_stream) ↓ CPA provider + credential + translation + transport ↓ configured physical model

02 / tasks 3-6

Routing core xây theo thứ tự phụ thuộc.

  1. Validated policy + capability registry. Reject config sai, không suy capability từ tên model, unknown không đáp ứng strict requirement.
  2. Weighted tier selection. Smooth weighted round robin trong tier cao nhất còn eligible; không retry cùng candidate.
  3. Bounded affinity. LRU TTL dùng session hash, không lưu prompt, invalidate theo config revision.
  4. Health and recovery. Classify failure, cooldown target-level, half-open probe và recovery xác định được bằng mock clock.

03 / tasks 7-10

Execution an toàn rồi mới đến persistence và dashboard.

Non-stream failover429/503 thử candidate cùng tier trước, hạ tier sau khi exhaust; 401 credential-specific không cooldown target.
Stream safetyRetry chỉ trước payload đầu tiên. Partial output là terminal, cancellation đóng host stream.
SQLite & metricsUsage aggregate phân biệt bundle/model; SQLite failure không block inference.
Authenticated managementValidate/apply/rollback revision qua management route, dashboard escape dữ liệu untrusted.
No credential surfaceBrowser, log, DB và metrics không mang OAuth, secret, prompt hay session raw value.
Direct host regressionPlugin disabled hoặc direct physical model vẫn giữ routing chuẩn của CLIProxyAPI.

04 / tasks 11-12

Vận hành và release có gate riêng.

Preflight chỉ đọc. Installer mặc định dry-run, backup trước mutation và rollback đúng artifact do nó tạo. Tài liệu ghi systemd, WAL backup/recovery, monitoring, OpenCode schema và ranh giới OAuth.

CI chạy format, vet, test, race, dashboard, vulnerability check, native amd64 load và disposable host test. Arm64 chỉ được đánh dấu supported sau native runner + ABI-load proof.
