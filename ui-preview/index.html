01 / execution boundary

Plugin chọn model. Host thực thi model.

Router chỉ bắt ba alias chat, research, code và route về executor của chính plugin. Executor chọn physical target, sau đó gọi callback của host để giữ nguyên provider authentication, refresh token, schema translation và transport policy.

02 / deterministic policy

Ưu tiên chất lượng, cân bằng có kiểm soát.

  1. Classify request. Đọc protocol, stream, tools, structured output, reasoning, context estimate và trusted session ID khi cấu hình cho phép.
  2. Honor valid affinity. Chỉ dùng binding còn hạn, còn tồn tại trong config revision và còn đạt capability.
  3. Enter highest eligible tier. Quality là policy do admin khai báo, không phải suy luận từ tên model.
  4. Select smoothly by weight. Smooth weighted round robin hoạt động trong tier, không starve healthy target.
  5. Fail over without recursion. Thử model cùng tier trước; chỉ hạ tier khi không còn candidate phù hợp.

03 / non-negotiable invariants

Những điều router không được làm.

Không OAuth thứ haiProvider authentication, refresh và credential scheduling thuộc CLIProxyAPI.
Không suy capability từ tên modelUnknown không thỏa strict requirement; provenance được lưu rõ.
Không nối hai streamFallback chỉ trước payload đầu tiên. Partial output là terminal.
Không lưu promptAffinity chỉ lưu hash session, target, expiry và config revision.
Không dashboard publicUI/API dùng management routes authenticated; không dùng resource route công khai.
Không claim Internet accessBundle research không tự cấp web search hay MCP tools.

04 / state & operations

Fast path ở memory, history ở SQLite.

Affinity LRU, cooldown và weighted scheduling tồn tại trong memory để không đưa SQLite vào request critical path. SQLite WAL lưu config revisions, capability registry/provenance, usage aggregate và health summaries. Lỗi telemetry phải được ghi nhận nhưng không được chặn inference.

Metrics chỉ dùng label cardinality thấp: bundle, target, tier, error class. Không session ID, credential hoặc raw request body trong log, DB hay metric label.

05 / evidence before release

Gate dựa trên test thực thi, không dựa trên lời hứa.

Gate A

Repository, source compatibility, attribution và ABI contract documented.

Gate B

Native plugin compile/load, ba alias, tier/weighted/fallback và host execution integration pass.

Gate C

Capability routing, affinity, cooldown, stream safety, dashboard, usage và SQLite restart pass.

Gate D

CI green, checksum artifacts, disposable staging, rollback và deployment documentation verified.

Local environment hiện thiếu C compiler; native shared-library validation phải chạy GitHub Actions hoặc Ubuntu staging có toolchain. Không được báo PASS cho ABI/arm64 trước evidence đó.
